**Docs (slice 842): `variable-ac-by-posture` is NOT A BUG — stale 2014 finding (closes the last Area-7 row)**
The L7 audit's "statblock AC is a single number; prone/posture AC variants (Ankheg 14/11) are dropped" row was 2014-based. Canon-verifying against `references/srd-markdown/`: the "11 while prone" is a 2014-PHB artifact (2014 Ankheg: "AC 14 (natural armor), 11 while prone"); SRD 5.2.1 gives **every monster a single AC number** — natural armor folded into a flat value, posture-based variants removed. The 2024 Ankheg is "AC 14"; a corpus-wide grep for "while prone" / "(natural armor)" / any dual AC returns zero matches. The engine's scalar `ac: z.number().int()` (Ankheg pack `ac: 14`) is the correct 2024 model — a posture-variable AC would be edition drift. The row is struck through (NOT A BUG) and moved to "Confirmed correct / by-design"; a new 3-test `slice-842` guard pins the Ankheg's flat AC 14, every monster carrying one scalar AC, and no monster carrying a posture/prone/dual-AC field. This resolves the last open Area-7 (monster-runtime) row. Doc + test only; no source change. (Side find, flagged for a separate content slice: the Ankheg's Acid Spray has drifted — pack `DC 13 / 3d6` vs SRD `DC 12 / 4d6`.) `tsc` clean; guard + doc audits green.

**Docs (slice 841): `disease-generic-condition` is NOT A BUG — stale 2014 finding**
The L7 audit's "no generic `diseased` condition; each disease is bespoke" row implied a 2014-based gap. Canon-verifying against `references/srd-markdown/`: SRD 5.2.1 **removed diseases as a general mechanic** — "Diseased" is not one of the 15 conditions, "disease" is absent from the glossary and every monster's traits, and the only spell naming it is **Detect Poison and Disease** (detection; there's no generic cure — **Lesser Restoration** ends only Blinded/Deafened/Paralyzed/Poisoned, the 2014 "or one disease" arm is gone). The lone in-scope case — the **Death Dog**'s — is correctly modeled as a Poisoned-variant (`category: 'disease'`, mirroring `category: 'curse'`) with its own RAW 24h-recurring-CON-save cure rider, not a shared generic condition (which 2024 doesn't have). A generic `diseased` condition would be edition drift. The row is struck through (NOT A BUG) and moved to "Confirmed correct / by-design"; a new 2-test `slice-841` guard pins no-generic-Diseased + the lone `category: disease` row being the Death Dog's with its own `recurringSave`. Doc + test only; no source change. `tsc` clean; guard + doc audits green.

**Feat (slice 840): Legendary Actions (Aboleth) — closes the `legendary-lair-actions` lineage**
The Aboleth's Legendary Actions (pool of 3, 4 In Lair, refreshed at turn-start, spent after another creature's turn). The engine owns the budget; the timing + underlying action are consumer-orchestrated. New statblock **`legendaryActions`** (`{ uses, usesInLair?, actions: [{ name, cost }] }`) + **`Character.legendaryActionsUsed`** counter refreshed at the creature's turn-start (a no-op reset in `applyTurnStarted` — deterministic, byte-safe for non-legendary combatants) + consumer-driven **`engine.plan.legendaryAction`** (validated spend → `LegendaryActionUsed`, throwing when the pool can't afford the cost; `inLair` raises the pool). The "after another creature's turn" timing is consumer-orchestrated and the underlying action (Lash = a Tentacle attack, Psychic Drain = Consume Memories + heal) is dispatched separately by the consumer — those Aboleth actions are the separate actions-population gap. Content: the Aboleth's menu (Lash, Psychic Drain). With slice 839 this fully closes `legendary-lair-actions` (the 2024 SRD folded lair into the legendary framework — no separate initiative-20 lair actions). New event + optional Character field (migration-safe); new 5-test slice-840. No new condition/effect kind/weapon → no doc-counts bump. `tsc` clean; planner-wiring + pack-integrity + migrations + fast suite green (620 files, 4697 passed).

**Feat (slice 839): Legendary Resistance — Aboleth / Sphinx of Lore / Unicorn**
Legendary creatures couldn't shrug off a failed save. Advances the L7 `legendary-lair-actions` row (the Legendary Resistance arm; the audit's "only Aboleth" was wrong — it's a trait on the Aboleth (3/4), Sphinx of Lore (3/4) and Unicorn (3) in scope). New statblock **`legendaryResistance`** (`{ usesPerDay, usesPerDayInLair? }`) + **`Character.legendaryResistanceUsed`** budget (reset on a Long Rest) + consumer-driven **`engine.plan.legendaryResistance`** (the Shield `preventedHit` shape): the consumer sees a legendary creature fail a save and calls it; the engine confirms the budgeted spend (throws when exhausted) + emits `LegendaryResistanceUsed`, and the consumer treats the save as a success (drops the fail consequences). `inLair` is a consumer fact raising the cap. Consumer-orchestrated rather than inline because a fully-inline version would thread a "consumer-decides" fact (don't burn a use on a Fireball half-save) through every save site — a genuine cross-cut. The 2024 SRD folded lair into the legendary framework (no separate initiative-20 lair actions); the **Legendary Actions** pool is split out as `legendary-actions-pool`. New event + optional Character field (migration-safe). New 6-test slice-839. No new condition/effect kind/weapon → no doc-counts bump. `tsc` clean; planner-wiring + pack-integrity + migrations + fast suite green (619 files, 4692 passed).

**Docs (slice 837): `weapon-material-qualifier` is NOT A BUG — stale 2014 finding**
The L7 audit's "`GrantResistance.qualifier` needs silvered/adamantine" row was 2014-based. Canon-verifying against `references/srd-markdown/`: SRD 5.2.1 **removed the weapon-material resistance qualifier entirely** — monster resistances are flat typed lists (Chain Devil: "Bludgeoning, Cold, Piercing, Slashing"; Clay Golem: "Bludgeoning, Piercing, Slashing"), the Werewolf has no Resistances line and the Stone Golem only Poison/Psychic immunity (the 2014 "nonmagical not silvered/adamantine" arm is gone). "Silvered" isn't a 2024 mechanic; "adamantine" is only an object-AC value + the Adamantine Armor crit rule. The pack already models every relevant creature with the flat 2024 resistance, and zero monsters use the qualifier — implementing silvered/adamantine would be edition drift. The row is struck through (NOT A BUG) and moved to "Confirmed correct / by-design"; a new 4-test `slice-837` guard pins the named creatures' flat resistances + the no-monster-uses-the-qualifier invariant. Doc + test only; no source change. `tsc` clean; guard + doc audits green.
