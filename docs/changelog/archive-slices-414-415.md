**Engine (slice 415): character-sheet spellcasting block (read layer, part 4)**

Extends the character-sheet view model with the spellcasting block. `buildCharacterSheet` now carries an optional `spellcasting?: SpellcastingView`, present only for characters with a spellcasting class or any castable spell (a plain fighter has none). It holds two parts: `classes` (one `SpellcastingClassView` per caster class with `ability` / `saveDC` / `attackBonus`, per-class because a multiclass caster can mix INT / WIS / CHA), built from the existing `computeSpellSaveDC` / `computeSpellAttackBonus`; and `spellsByLevel`, the character's castable spells grouped by level (ascending, each group name-sorted), each entry flagged `prepared` (in `preparedSpells`) and `alwaysPrepared` (granted by a feature / item with no prepare cost). Spell slots are already on the base `DerivedCharacter`, so the block doesn't duplicate them.

The spell-list union mirrors `effectiveSpellList` (known + prepared + granted) but is inlined here because the sheet needs the granted entries' `preparation` field to flag always-prepared / at-will spells, which `effectiveSpellList` collapses to bare ids. Spell ids with no matching definition are skipped.

New public exports: `SpellcastingView` / `SpellcastingClassView` / `SpellListEntry` / `SpellLevelGroup` (all type-only). Deferred to follow-ups: the unarmed strike entry, effective speeds, and the inventory / equipment summary.

Uncle Bob audit (engine slice): **Names** `spellcastingView` / `spellcastingClasses` / `spellLevelGroups` + the four view types say what they hold. **DRY** reuses `computeSpellSaveDC` / `computeSpellAttackBonus`; the one inlined union (vs `effectiveSpellList`) is justified in a comment (it needs the granted `preparation` field the canonical function discards). **SRP** `spellcastingClasses` only builds per-class DC/attack; `spellLevelGroups` only builds the grouped list; `spellcastingView` composes + decides presence. **Magic numbers** none (DC base 8 + PB live in the DC derivation; spell levels come from definitions). **at-threading** n/a (pure reads). **Mechanical outcomes asserted** non-caster has no block; a wizard's per-class save DC = 8 + PB + INT mod and attack = PB + INT mod; spells group by level ascending, name-sorted, with correct prepared flags; dangling spell ids skipped. **Tests** 4 cases (a fighter + a starter-pack wizard). No content change. No em/en dashes. `tsc --noEmit` clean; full suite green; contract export snapshot updated.

**Engine (slice 414): character-sheet attacks list (read layer, part 3)**

Extends the slice-413 character-sheet view model with the `attacks` list a sheet's weapons section renders. `buildCharacterSheet` now carries `attacks: AttackView[]`, one entry per weapon in the character's inventory (in inventory order): `attackBonus` (to-hit), a static `damage` line `{ dice, modifier, type }`, `versatileDamage` for versatile weapons (the two-handed die), plus `properties` / `range` / `mastery`. The to-hit reuses `computeAttackBonus`; the new derivation is `computeWeaponDamage(input) -> WeaponDamageResult` in `src/derive/attack.ts`, which composes the weapon die with the attack-ability modifier (STR, or DEX for ranged / the better of the two for finesse, mirroring the to-hit ability choice) plus flat magic / buff / enchantment damage bonuses. Conditional roll-time riders (Sneak Attack, Great Weapon Fighting's die floor, Martial Arts scaling, off-hand no-modifier) are deliberately NOT folded into the static line; those resolve in the attack planner per attack context.

Refactor: the weapon-instance resolution + attack-ability-mod logic that `computeAttackBonus` inlined is extracted to shared `resolveWeapon` / `attackAbility` helpers, now used by both the to-hit and damage derivations (no behavior change to `computeAttackBonus`, verified by the unchanged attack test suite).

New public exports: `computeWeaponDamage` + `WeaponDamage` / `WeaponDamageResult` (derive), and `AttackView` (the sheet's per-weapon shape). Deferred to follow-ups: the **unarmed strike** entry (RAW 1 + STR mod, or Martial Arts die for monks), **spell save DC / attack bonus**, **effective speeds**, and the **inventory / equipment summary**.

Uncle Bob audit (engine slice): **Names** `computeWeaponDamage` / `WeaponDamage` / `AttackView` / `resolveWeapon` / `attackAbility` / `attackViews` say what they are. **DRY** the extraction removes the duplicated weapon-resolution + ability-mod between the to-hit and damage paths; the view reuses both derivations rather than recomputing. **SRP** `computeWeaponDamage` only builds the damage line; `attackViews` only enumerates inventory weapons; the rule lives in the derivation. **Magic numbers** none (dice + types come from the weapon definition). **at-threading** n/a (pure reads). **Mechanical outcomes asserted** one entry per inventory weapon in order; melee uses STR, ranged uses DEX, finesse picks the higher (both branches tested); versatile carries the two-handed line; flat magic / buff bonuses add; dangling instance ids skipped. **Tests** 7 attack cases over the fighter fixture (longsword / rapier / longbow), plus the unchanged `computeAttackBonus` suite proving the refactor is behavior-preserving. No content change. No em/en dashes. `tsc --noEmit` clean; full suite green; contract export snapshot updated.
