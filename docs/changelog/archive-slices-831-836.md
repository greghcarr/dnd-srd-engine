**Feat (slice 836): ooze Split (Black Pudding / Ochre Jelly) — closes `ooze-split-on-damage`**
The oozes' Split was inert — and its response (half the *current* HP, one size smaller, original replaced) is beyond the fixed-HP/same-size `SpawnCreature` action. New statblock **`split`** spec (`{ damageTypes, minHp }`) + consumer-driven **`engine.plan.oozeSplit`**: the consumer detects the trigger (slashing/lightning damage or Bloodied — it has the DamageApplied events + HP) and calls it; the engine validates RAW eligibility (Large/Medium, ≥10 HP) and emits two `CharacterCreated` of the same statblock one size smaller (a `sizeOverride`) at `floor(currentHP/2)` each + `CreatureDestroyed` on the original (it's replaced). Placement + the "acts on its Initiative" insertion stay consumer-managed (positions/encounter are out of engine scope, like the Wraith/Wight spawns). The 35-field spawn snapshot was extracted from the Troll's `fireSpawnCreature` into a shared `buildSpawnedCharacter` (rule-of-two; the Troll path stays byte-compatible). Content: `split` on Black Pudding (CR 4) + Ochre Jelly (CR 2). New 5-test slice-836. No new condition/event/effect kind/weapon → no doc-counts bump. `tsc` clean; planner-wiring + pack-integrity + Troll test + fast suite green (616 files, 4678 passed).

**Feat (slice 835): Shadow Strength Drain — ability-score-drain accumulator (closes `drain-undead-arms` lineage)**
The Shadow's Draining Swipe drains a target's Strength (1d4/hit, dies at STR 0) — unlike the max-HP drain, an ability score feeds ~15 derivations. New **`character.abilityDrain`** per-ability accumulator (an `AbilityScoreDrained` event + reducer, restored on a Long Rest), subtracted **last** (clamped to 1) via a new optional 4th **`drain`** param on `effectiveAbilityScore`. Threaded through every **combat/derived** consumer — attack to-hit/damage/cleave, saves, checks, AC, spell DC + attack, the heavy-weapon STR gate, the armor-STR speed penalty, hit-die heal, the sheet — but **not** the build-time validators (multiclass prereq, feat eligibility), which keep the innate score. New on-hit weapon **`drainsAbility { ability, dice }`** rider (the Shadow's `shadow-draining-swipe`, 1d6+2 necrotic + STR 1d4) with the STR-0 instant-death gate (`CreatureDestroyed` when base − cumulative drain ≤ 0). The on-kill Shadow spawn stays consumer/DM-managed. The cross-cutting change is opt-in (drain undefined for every existing character) → all conformance + golden suites byte-unchanged. +1 weapon → 239→240; new event + optional Character field (migration-safe). New 6-test slice-835. `tsc` clean; pack-integrity + doc-counts + migrations + fast suite green (614 files, 4671 passed).
Detail: [slice-835.md](slice-835.md).

**Feat (slice 834): Wight Life Drain — save-action max-HP drain**
The Wight's Life Drain is a CON-save action, so slice 832's weapon `drainsMaxHp` couldn't carry it. New **`SaveActionSpec.onFail.drainMaxHp`** arm: a failed save reduces the target's Hit Point maximum by the post-mitigation damage taken (the same slice-832 `life-drained` mechanism, restored on a Long Rest). The cumulative remove-then-readd logic was extracted into a shared **`planLifeDrainEvents`** helper (the rule-of-three) now driving both the weapon on-hit drain (Specter/Wraith) and the save-action arm (Wight); `attack.ts` refactored onto it byte-compatibly (slice-832 test + fuzz goldens confirm). Content: the Wight's Life Drain save-action (CON DC 13, 1d8+2 necrotic). Advances the L7 `drain-undead-extra-arms` row; split out `drain-undead-shadow` for the Shadow STR-score drain + the Wight/Shadow on-kill spawns (consumer/DM-managed). No new condition/effect kind (reuses `life-drained`) → no doc-counts bump. New 5-test slice-834. `tsc` clean; pack-integrity + fast suite green (614 files, 4667 passed).
Detail: [slice-834.md](slice-834.md).

**Infra (slice 833): combat-fuzz drop-in opponent character (PvP)**
The PvP mirror of the slice-778 player drop-in: a new `FuzzBattleOptions.opponentCharacter` (`{ character, itemInstances }`) seats a second caller-supplied sheet into team B[0] verbatim (own id / class / level / gear), so dnd-web can run real-vs-real 1v1. Built next to `playerCharacterBuilt` via the same `buildFromPlayerCharacter`; the `teamB` 'pc' branch is now index-aware and still draws-and-discards B[0]'s shared `buildL1` (keeping the seed stream aligned, exactly how teamA[0] seats the player), then seats the drop-in at index 0; the item-acquire loop emits its own instances (no synthesis) and the `level > 1` loop never re-levels it. An INDEPENDENT axis from the seed, only meaningful for the 'pc' team (ignored for `vs='monster'`). The no-`opponentCharacter` path stays byte-identical — verified by the full fuzz golden + matrix tier (139 tests, incl. the 85-test `fuzz-matrix`). New 5-test slice-833 (both drop-ins seated verbatim, seed-determinism, no seed-stream perturbation, own-level, vs=monster ignore). `tsc` clean; fast suite + fuzz goldens green.

**Feat (slice 832): undead Life Drain (max-HP drain) — Specter / Wraith**
Undead Life Drain ("its Hit Point maximum decreases by an amount equal to the damage taken") was inert, and the Specter / Wraith had no weapon wired at all. Advances the [L7 audit](l7-completion-audit.md) `drain-undead-arms` divergence (the attack-roll max-HP-drain arm). New **`WeaponDefinition.drainsMaxHp`** flag: a hit applies a cumulative **`life-drained`** condition carrying a negative `hpMaxBonusDelta` = the post-mitigation damage taken (the existing ConditionApplied reducer lowers `hp.maxBonus` — no new reducer; remove-then-readd keeps one cumulative entry since the reducer dedupes by id and the in-scope drainers strike once per turn). Restored on a Long Rest: `planLongRest` emits a `ConditionRemoved` (reversing the delta) for `endsOn`-longRest conditions carrying a max-HP delta, before `LongRestEnded` resets HP — precise so exhaustion / rage are untouched (the 2024 default, per the Mummy/Death-Dog "doesn't return" exceptions). Content: the previously-unmodeled **Specter** (2d6 necrotic) + **Wraith** (4d8+3 necrotic) Life Drain weapons + actions (exact dice baked via `noAbilityModifierDamage` so the drain matches the SRD line). Split out `drain-undead-extra-arms` for the Wight (save-action drain + zombie spawn) and Shadow (STR-score drain + spawn). New condition → 167 (152 rider); +2 weapons → 239; bumped the conditions + items citations. New 4-test slice-832 (drain on hit, accumulation, Long-Rest restoration). `tsc` clean; pack-integrity + doc-counts green; fast suite green (613 files, 4662 passed).
Detail: [slice-832.md](slice-832.md).

**Feat (slice 831): monster Parry reaction — closes `monster-parry-reaction`**
Several martial NPCs print a Parry reaction (hit by a melee attack → +N AC vs that attack, possibly a miss) that the engine couldn't resolve — there was no generic monster reaction. Structurally `planShield` without the slot. New **`GrantParry { acBonus }`** effect (folded by `buildEffectStack` into `parryBonus()`) + **`engine.plan.parry`** (reads the bonus off the effect stack, consumes the reaction, emits a pure-notification `ParryUsed` with `preventedHit = triggeringAttackTotal < originalAC + acBonus`; the consumer drops the damage chain on a miss, same contract as Shield's `ShieldCast`) + a **`parry` reaction-affordance descriptor** (`availableReactions` / `reactionsForTrigger`, melee-only via `event.attackKind`, offered only when +N could flip the hit, monster-gated on `statblockId`). SRD-verified content: **Bandit Captain / Knight / Warrior Veteran / Noble +2, Gladiator +3** (verified the "the bandit" Parry sits on the CR 2 Captain statblock, the "## Warriors" Parry on the CR 3 Veteran; Erinyes +4 / Marilith +5 are out of scope at CR 12 / 16). See-attacker + wielding-a-weapon stay consumer-side. New effect kind → EFFECT_KINDS 69 → 70 (bumped the eight pinned citations). New 7-test slice-831. `tsc` clean; planner-wiring + doc-counts green; fast suite green (612 files, 4658 passed).
