# Slice 644 — tests: fuzz matrix audit (L1 + L2 across shapes + rests)

**Type:** Tests (audit-only). Supersedes [slice 643's L2 fuzz floor](slice-643.md).

The slice-643 L2 fuzz floor was deliberately minimal — one cell (L2 / 1v1 PC-vs-PC / rest=none / 20 seeds) sufficient to close the L2-complete claim. Two structural gaps remained:

1. **No L1 fuzz coverage in CI at all.** The L1 fuzz cycle (slices 620-627) ran thousands of seeds during development and surfaced 7 real bugs the static tests missed (concentration RAW dispatch, rider-damage triggers, Vex auto-expiry, Innate Sorcery class gate, Monk dex-attack scaling, Graze hit/miss gate, on-hit mastery 0-damage gate). None of that fuzz coverage was promoted to a permanent guard before this slice. L1 has *less* CI fuzz coverage than L2.
2. **Combat-fuzz CLI exposes four knobs** (level, teamSize, vs, rest) but slice 643 used only one combination. Cells like "L2 with long rest" (which exercises the rest reducers + per-rest resource refills under fuzz) and "1v1 vs monster" (which exercises monster planners — Multiattack, Pack Tactics, breath weapons) were uncovered.

Slice 644 closes both. **24-cell matrix × 20 seeds per cell = 480 battles** per CI run. ~5 sec wall-clock.

## Matrix

| Axis | Values |
|---|---|
| Level | 1, 2 |
| Shape | 1v1 PC, 2v2 PC, 1v1 monster, 2v2 monster |
| Rest cadence | none, short, long |

All 24 cells × 20 seeds pass with the current engine. The L1-side cells extend CI fuzz coverage where there was none; the L2-side cells supersede slice 643's single-cell floor with the same seed count plus rests + monsters + 2v2 across the board.

## Audit (Uncle Bob)

- **Names**: `LEVELS`, `SHAPES`, `RESTS`, `SEEDS_PER_CELL` — every axis named at the top of the file. Test title format `L${level} ${shape.label} rest=${rest}: ${SEEDS_PER_CELL} seeds...` makes each cell's identity scannable in the test output.
- **DRY**: the matrix is generated by nested `for...of` over the three axis arrays. Adding a fifth shape (e.g. 3v3) or a new level (L3, L4) is a one-line array push; the inner test body doesn't change. Single source of truth for each axis.
- **SRP**: the audit's one job is "every reasonable L1 + L2 combat configuration completes without throwing." It deliberately does not assert on winners, durations, balance, or RAW-correctness — those belong to other audits or per-feature tests. The fuzz harness lives in `scripts/combat-fuzz-core.ts` (slice 600) and is shared with the CLI; this audit is a thin parametrization.
- **Magic numbers / strings**: `SEEDS_PER_CELL = 20` matches the slice-643 floor it supersedes (no per-cell coverage regression). Cell count `24 = 2 * 4 * 3` is asserted by the enumeration sanity test so an axis added without updating the assertion trips loudly.
- **Pattern-check**: when an L3 floor lands, this audit takes an `LEVELS = [1, 2, 3]` edit and the L3 cells light up automatically. If a future slice introduces a new combat shape (e.g. solo PvE with reaction-only enemies), the SHAPES array takes one row. No new audit file per axis variant.

## What this audit does NOT cover (still open)

- **Multiclass fuzz** at any level. The combat-fuzz CLI builds single-class PCs only; extending it to multiclass parties is its own engineering slice. The slice-642 multiclass build audit covers "the pair builds + derives," not "the pair fights."
- **Higher levels** (L3+). Those are out of L2 scope; future hardening cycles add L3+ cells.
- **Seed-level reproducibility / transcript byte-stability**. The CLI's job; this audit is the always-on canary, not the reproducibility ledger.
- **Soft balance** (e.g. "warlock wins 70% of L2 PC fights"). The audit accepts any outcome.
