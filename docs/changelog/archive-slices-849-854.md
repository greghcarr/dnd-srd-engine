**Feat (slice 852): Banishment — CHA save → Incapacitated (concentration-bound) — closes `l4-banishment`**
The spell shipped `mechanicalEffects: []` — a cast did nothing. RAW: "must succeed on a Charisma saving throw or be transported to a harmless demiplane ... While there, the target has the Incapacitated condition. When the spell ends, the target reappears." RAW's only mechanical hook is the Incapacitated condition, so this is a thin wire: the mechanic is `{ save CHA, conditionOnFail: 'banished-active' }`; the new `banished-active` condition carries `effects: []` and the action-block is engine-coded by adding its id to `ACTION_BLOCKING_CONDITIONS` (`_actor-state.ts`) — the held-paralyzed-active / sleep-drowsy-active path. It's concentration-bound (`planSaveMechanic` stamps `sourceEffectInstanceId`), so it lifts when the caster's Concentration ends and the target returns; `autoExpiry { 10 rounds }` caps the 1 minute. `banished-active` joins the `EFFECT_LESS_OK` allowlist. Deferred (consumer/positional/narrative): the demiplane removal/untargetability (engine models only the Incapacitated), the reappear placement, the Aberration/Celestial/Elemental/Fey/Fiend "doesn't return after 1 min" plane-transport arm, and the upcast "+1 target/slot". +1 condition (172 → 173; rider 157 → 158; carry unchanged — effect-less); coverage snapshot unchanged; `spell-coverage` flips `banishment` skip → save. New 5-test slice-852 (save shape; action-block membership + cap; failed save banishes + binds to Concentration; success unaffected; second Concentration spell lifts it). `tsc` clean; `test:fast` + doc audits green.

The sphere is immune to all damage, and a creature inside can't be damaged by attacks or effects originating from outside." Content-only fix reusing two shipped primitives (no engine/schema change): the **cast arm** is the slice-849 unwilling-save-on-buff — `{ kind: 'buff', conditionId: 'resilient-sphere-enclosed', unwillingSave: { ability: 'DEX' } }` (a willing target is enclosed with no save; an unwilling one, named via `intent.unwillingTargetIds`, rolls DEX vs the caster's spell DC), concentration-bound; the **effect arm** is `GrantImmunity { damageType: 'all' }` on the new `resilient-sphere-enclosed` condition, so `mitigateDamage` returns 0/`immune` for any source (the trapped creature can't be damaged — positions-free, every attacker is "outside"). `autoExpiry { 10 rounds }` caps the 1 minute. **Content (slice 850): Blindness/Deafness — Blinded/Deafened choice + CON save-ends — closes `blindness-deafness-no-choice-no-saveends`**
RAW: the target has "the Blinded or Deafened condition (your choice)" and "at the end of each of its turns ... repeats the save, ending the spell on itself on a success." The engine hardwired `conditionOnFail: 'blinded'` (no Deafened choice) and the shared `blinded` deliberately has `recurringSave: null` (Blinded from a monster's gaze must NOT auto-end), so the end-of-turn save never fired. Content-only fix reusing three shipped primitives: the CON save mechanic swapped the hardwired condition for `casterChoosesVariant` (the Command shape) over two new spell-only variants — `blindness-deafness-blinded` / `-deafened` — each carrying the base Blinded/Deafened effects directly (shared conditions untouched) plus a `recurringSave { CON, turnEnd, removeCondition }` with no `fixedDC` (→ resolves the caster's spell DC from `sourceCharacterId`, the Hold Person path) and `autoExpiry { 10 rounds, turnEnd }` as the 1-minute cap. The consumer ticks `tickRecurringSave` at the target's turn-end; a success ends the spell. No engine/schema/event change. +2 conditions (169 → 171; rider 154 → 156); coverage snapshot gains both wired variants (`-u`). New 6-test slice-850 (the caster choice; both variants' effects + save-ends shape; a failed cast applies the chosen variant sourced to the caster; the turn-end save resolves vs the caster DC 15 and ends the spell on a success / leaves it on a fail). Upcast "+1 target/slot" stays a targeting-seam (Area 3) concern. `tsc` clean; `test:fast` + doc audits green.

**Feat (slice 849): Enlarge/Reduce unwilling-target CON save — closes the "or-save" arm of `enlarge-reduce-no-damage-rider-or-save`**
RAW: "If the target is an unwilling creature, it can make a Constitution saving throw. On a successful save, the spell has no effect." The engine modeled Enlarge/Reduce as a pure `buff` that applied to every target with **no save** — so an enemy could be Reduced (Disadvantage on STR checks/saves) against its will with no roll. New generic **save-gated-buff** primitive: the `buff` SpellMechanic carries `unwillingSave { ability }`, the consumer names the unwilling targets via `intent.unwillingTargetIds` (willingness is consumer-owned creature-relationship state, a seam like `cover` / `lightLevel`), and `planBuffMechanic` (now threaded `rng` + the casting class/ability) rolls that save vs the caster's spell save DC through the shared `rollSaveAgainstDC` — a success skips the condition ("no effect"), a `SaveRolled` event is emitted either way. Empty unless both halves are present → willing targets and every other buff spell are byte-identical. Enlarge/Reduce wired `unwillingSave { CON }` (above the variant fork, so it gates both enlarge and reduce). The ±1d4 weapon-damage rider is **split** to a tracked follow-up (`enlarge-reduce-no-damage-rider`) — Reduce's −1d4-with-min-1-floor needs a negative-damage rider the pipeline lacks. New 5-test slice-849 (CON `unwillingSave` present; willing target buffed with no save; unwilling fail → Enlarged; unwilling success → resists; Reduce variant gated). No condition/effect/weapon added (counts + coverage snapshot unchanged). `tsc` clean; `test:fast` + doc audits green.
