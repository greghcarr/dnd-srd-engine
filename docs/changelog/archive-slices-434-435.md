**Infra (slice 434): doc code-example typecheck audit (the next guard slice 432 flagged)**

Builds the guard slice 432 named as next: the doc code examples we present as runnable are now compiled against the real public barrel in CI, so a renamed / removed export or a method that never existed (the bogus `engine.handlers.register(...)` slice 433 found by hand) breaks CI in the same commit instead of shipping copy-paste-broken example code. This closes the last class of doc drift the link + count guards couldn't reach: prose claims, links, and counts were already CI-guarded; example code was not.

New [tests/audit/doc-examples.test.ts](../../tests/audit/doc-examples.test.ts) is **opt-in by design**. Most doc `ts` blocks are reference sketches with intentional elisions (`...`, `/* ... */`), undeclared setup variables, or signature-only pseudo-syntax (`createEngine({ contentPacks, rng, handlers? })`); compiling those would be all false positives. A block is checked only when the line directly above its fence is the GitHub-invisible marker `<!-- typecheck -->` (starts a synthetic module) or `<!-- typecheck:continue -->` (appends to that doc's current module, so a multi-step walkthrough builds up state and is checked as one program). Each module is written to a temp `.ts` and compiled with the project's own tsconfig (so `dnd-srd-engine` resolves to `src/index.ts` via its path mapping, and the README's "work against source" `./src/index.js` is normalized to the same barrel); DOM lib is added so `console` resolves. Marked the two canonical copy-paste paths: the README quickstart and the getting-started walkthrough (blocks 2-6 as one program). The CLAUDE.md "CI-guarded or not stated" norm now documents the marker convention (mark runnable examples; leave sketches unmarked) and lists this audit alongside doc-links / doc-counts.

Uncle Bob audit: **Names** `modulesIn` / `normalizeImports` / `START_MARKER` say what they do; the file walker mirrors doc-links' shape. **DRY** the markdown-file walker is duplicated from doc-links (single ~12-line helper, two call sites, below the abstraction threshold for a shared test util; declined to factor a `tests/audit/_md.ts` for two readers). **SRP** parse (markers -> modules), normalize, compile, and attribute-failures are separate steps. **Magic numbers** none beyond the marker string constants. **Mechanical outcomes asserted** the marked examples compile clean (proven by injecting `engine.handlers.register` + `derive.nonexistentMethod` and watching tsc reject both with the doc + module-start line attributed); the sanity probe asserts the audit isn't vacuous (>= 2 modules found). **Tests** prevents the broken-example regression class and pins the onboarding examples consumers actually copy. No engine/content/public-surface change. Full suite + tsc green.
