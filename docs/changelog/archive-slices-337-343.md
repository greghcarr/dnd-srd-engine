**Content: Enthrall wired (slice 343)**

Pure content slice on existing primitives. **Enthrall** (L2, concentration) now wires as a `save` mechanic (WIS, `conditionOnFail: 'enthralled-active'`); the new `enthralled-active` condition carries `AddModifier { target: { kind: 'skill', skill: 'perception' }, value: -10 }`, the RAW 2024 "-10 penalty to Wisdom (Perception) checks." The condition is concentration-linked (cast-spell ties `conditionOnFail` conditions to the concentration effect, so it clears when the caster's concentration drops, same lifecycle as Hold Person). Skill-targeted `AddModifier` is the same shape Pass without Trace already uses (+10 Stealth), and the ability-check derive already sums it.

RAW deviations (documented on the condition): the parallel "-10 to Passive Perception" is not modeled (no derive sums modifiers into passive Perception today; only the active-check penalty is wired), and the "any creature you or your companions are fighting automatically succeeds on the save" clause is consumer-managed (the engine doesn't model combat relationships, so the caster omits such creatures from the cast's targets).

Spell coverage: 193 -> 194 wired, 88 -> 87 deferred. Conditions 118 -> 119. New [tests/unit/engine/slice-343-enthrall.test.ts](../../tests/unit/engine/slice-343-enthrall.test.ts) pins the -10 Perception penalty (and that other WIS skills are unaffected) and the cast chain (WIS save; failed save applies the condition, successful save does not); enthrall flipped from `skip` to an active `save` expectation. Coverage snapshot regenerated (+1 condition).

Content audit (RAW match): the save ability (WIS), the penalty target (Perception checks) and magnitude (-10), and the concentration linkage all match SRD 5.2.1 Enthrall; the two documented deviations are the passive-Perception arm (no consumer) and the auto-success-while-fighting clause (no combat-relationship model). No new primitive; `tsc --noEmit` clean.

**Engine: `planDimensionDoor` teleport planner (slice 342)**

New dedicated `planDimensionDoor` ([src/engine/plan/movement.ts](../../src/engine/plan/movement.ts)) + `engine.plan.dimensionDoor`. RAW 2024 Dimension Door: 4th-level conjuration, Action, range 500 ft. The caster teleports to a location within range and may bring one willing creature that starts within 5 ft, arriving within 5 ft of the destination. Emits `SpellCastDeclared` + `SpellSlotConsumed(4+)` + `ActionEconomyConsumed('action')` + `CombatantMoved` (caster) + optional `CombatantMoved` (ally); consumes no RNG. Guards: 4th-level minimum, knows/prepared the spell, active combatant, action not yet used, destination within 500 ft (Chebyshev), ally within 5 ft of caster and arriving within 5 ft of the destination (and not the caster's own space). The RAW "arrive in an occupied space -> 4d6 Force, teleport fails" clause is modeled by *rejecting* an occupied destination, the same positioning stance as Misty Step / Thunder Step (the engine treats occupancy as the consumer's responsibility rather than dealing failure damage).

Wired into the public surface alongside the other teleport planners ([plan/index.ts](../../src/engine/plan/index.ts), the `Engine` interface + impl in [engine/index.ts](../../src/engine/index.ts), the `DimensionDoorIntent` re-export in [src/index.ts](../../src/index.ts) next to `MistyStepIntent`).

Spell coverage: 192 -> 193 wired, 89 -> 88 deferred (the cross-plane / teleport cluster drops to the long-range / planar entries the engine doesn't position). New [tests/unit/engine/slice-342-dimension-door.test.ts](../../tests/unit/engine/slice-342-dimension-door.test.ts) pins the self-only chain, the ally move, all five reject guards, and replay-equivalence; the coverage smoke test's dimension-door reason updated from "no dedicated planner yet" to the shipped planner.

Uncle Bob audit: **Names** `planDimensionDoor` / `DimensionDoorIntent` match the teleport-planner naming (Misty Step, Thunder Step). **DRY** reuses `findCombatant` / `chebyshevDistance` / `assertActorCanAct` and the `CombatantMoved`-with-`feetTraveled: 0` teleport shape; a local `assertUnoccupied` covers the caster and ally destinations rather than two copies. **SRP** the planner validates + emits movement only; no damage path (unlike Thunder Step). **Magic numbers** the 500 ft range, 4th-level minimum, and 5 ft proximity / arrival are named constants. **at-threading** single `nowIso()` to every event; no RNG. **Mechanical outcomes asserted** event order + slot level, one move (self) vs two (ally), and each guard (range, ally proximity, ally arrival, occupancy, slot level); replay-equivalence proves the RNG-free path. **Tests** prevent the ally move leaking when no ally is passed, the guards regressing, and non-deterministic replay. No em/en dashes. `tsc --noEmit` clean.

**Engine + content: multi-damage save mechanic + Flame Strike (slice 341)**

The `save` `SpellMechanic` gained an optional `additionalDamage` array (each entry: `damageDice` + `damageType` + its own `extraDicePerSlotLevel`). Each component is rolled once for the spell (AOE), takes the same success / Evasion halving as the primary `damageDice`, and lands as its own component in the single `DamageApplied` so per-type resistance / immunity is honored independently. Canonical user **Flame Strike** (DEX save, 5d6 Fire + 5d6 Radiant, half on success, both types +1d6 per slot above 5th) is the RAW 2024 shape; a creature resistant to one type still takes the other in full.

Backward-compatible: spells without `additionalDamage` roll and emit exactly as before (the components array reduces to the single primary component, no extra RNG consumed), so the ~60 existing save spells and their transcripts are unchanged.

Spell coverage: 191 -> 192 wired, 90 -> 89 deferred (the multi-damage-AoE cluster drops to prismatic-spray / meteor-swarm / prismatic-wall, which additionally need multi-AoE / RNG-damage-table shapes). New [tests/unit/engine/slice-341-flame-strike.test.ts](../../tests/unit/engine/slice-341-flame-strike.test.ts) pins the two-component DamageApplied (Fire + Radiant), the per-slot upcast on both types, and replay-equivalence; flame-strike flipped from `skip` to an active `save` expectation in the coverage smoke test.

Uncle Bob audit: **Names** `additionalDamage` / `additionalBase` / `outcomeAmount` read as what they hold. **DRY** the success/Evasion halving was factored into one `outcomeAmount(raw)` applied to the primary and every additional component, replacing the inline `finalAmount`; mitigation + fatal-intercept run once over the merged component list. **SRP** the mechanic still does one thing (a save with damage); the multi-type is just more components into the existing pipeline. **Magic numbers** the 5d6 / +1d6-per-slot live in RAW-cited pack content. **at-threading** unchanged; additional dice roll in the planner alongside the primary, baked into `DamageApplied`. **Mechanical outcomes asserted** one DamageApplied carrying both `fire` and `radiant`, each within a 5d6 roll, both scaling on upcast; replay-equivalence. **Tests** prevent the second component being dropped or merged into the wrong type, and a regression in single-component spells (full suite). No em/en dashes. `tsc --noEmit` clean.

**Engine + content: `hp-threshold` condition arm + Power Word Stun, with a Hold Person action-blocking fix (slice 339)**

Added a `condition` arm to the slice-338 `hp-threshold` mechanic (alongside `destroy` / `damage`): it applies a condition by id, honoring condition immunity. Canonical user **Power Word Stun** (threshold 150): at or below, the new `power-word-stunned-active` condition (Stunned's auto-fail STR/DEX saves + a recurring CON save at each turn-end that ends it, the RAW "Constitution saving throw at the end of each of its turns"); above, `power-word-speed-zero-active` (Speed 0 for one round, the RAW "its Speed is 0 until the start of your next turn"). Both conditions mirror the existing `held-paralyzed-active` spell-bound-variant pattern.

Pattern-check (the variant-recognition gap surfaced while wiring the stun arm): `ACTION_BLOCKING_CONDITIONS` in [src/engine/plan/_actor-state.ts](../../src/engine/plan/_actor-state.ts) is an id allowlist, and the spell-bound incapacitating variant `held-paralyzed-active` was **missing** from it, so a Hold Person / Hold Monster target could still take actions despite RAW Paralyzed including Incapacitated. Added both `held-paralyzed-active` (the latent fix) and `power-word-stunned-active`.

RAW deviations (documented on the conditions, consistent with `held-paralyzed-active`'s existing approximations): a creature immune to the bare `stunned` condition is not auto-detected as immune to the `power-word-stunned-active` variant id; the Speed-0 arm expires at the bearer's next turn-end rather than the caster's next-turn start.

Spell coverage: 190 -> 191 wired, 91 -> 90 deferred (HP-threshold cluster down to divine-word + power-word-heal). Conditions 116 -> 118. New [tests/unit/engine/slice-339-power-word-stun.test.ts](../../tests/unit/engine/slice-339-power-word-stun.test.ts) pins both arms (stun is action-blocking, speed-0 is not), the threshold boundary, replay-equivalence, and the action-blocking fix for both variants; power-word-stun flipped from `skip` to an active `buff` expectation in the coverage smoke test. Coverage snapshot regenerated (+2 conditions).

Uncle Bob audit: **Names** the `condition` arm + `power-word-stunned-active` / `power-word-speed-zero-active` read as the rulebook. **DRY** the arm reuses the save mechanic's immunity-checked `ConditionApplied` shape; the conditions reuse the `held-paralyzed-active` variant template rather than a new mechanism. **SRP** the arm only emits a (immunity-gated) condition; recurring-save + auto-expiry are condition-side declarations resolved by their existing planners. **Magic numbers** the 150 threshold lives in RAW-cited pack content. **at-threading** single `at`; `causedByEventId` set to the declared cast. **Mechanical outcomes asserted** which condition per arm, action-blocking on the stun arm but not the speed-0 arm, the boundary at exactly 150, and the `ACTION_BLOCKING_CONDITIONS` membership fix. **Tests** prevent arm inversion, the speed-0 arm incapacitating, the Hold Person can't-act regression, and non-deterministic replay. No em/en dashes. `tsc --noEmit` clean.

**Engine + content: `hp-threshold` spell mechanic + Power Word Kill (slice 338)**

New `hp-threshold` `SpellMechanic`: the spell reads each target's current Hit Points and applies one of two arms, `atOrBelow` (current HP <= `threshold`) or `above` (optional). Each arm is `destroy` (emits the slice-323 `CreatureDestroyed` instant-death event, bypassing death saves) or `damage` (dice + type, run through the same `mitigateDamage` + `interceptFatalDamage` pipeline as any spell damage). Canonical user: **Power Word Kill** (threshold 100, destroy at or below, 12d12 psychic above) is the RAW 2024 shape ("If the target has 100 Hit Points or fewer, it dies. Otherwise, it takes 12d12 Psychic damage"). Wired in [src/engine/plan/cast-spell.ts](../../src/engine/plan/cast-spell.ts) via `planHpThresholdMechanic` + the dispatch case; schema in [src/schemas/content/spell.ts](../../src/schemas/content/spell.ts).

This drains the largest fully-mechanical row from the post-slice-337 priority queue. The two-arm shape extends to the deferred siblings without reshaping the dispatch: Power Word Stun needs a `condition` arm kind (Stunned + recurring CON save, else Speed 0), Divine Word a multi-threshold tiered variant, Power Word Heal a heal + multi-condition-remove arm. Spell coverage: 189 -> 190 wired, 92 -> 91 deferred (gaps-spells.md L9 + the starter-pack-gaps.md Coverage row updated; the slice-337 count audit stays green).

The coverage smoke test gained a `destroy` expectation kind asserting `CreatureDestroyed`; power-word-kill flipped from `skip` to that active expectation. New [tests/unit/engine/slice-338-power-word-kill.test.ts](../../tests/unit/engine/slice-338-power-word-kill.test.ts) pins both arms (80-HP target destroyed, no damage roll; 150-HP target takes 12d12 psychic in [12,144], no destroy), the threshold boundary (exactly 100 destroyed), and replay-equivalence for both.

Uncle Bob audit: **Names** `hp-threshold` / `atOrBelow` / `above` / `planHpThresholdMechanic` read as the rulebook reads. **DRY** the `damage` arm reuses the existing mitigation + fatal-intercept + concentration-break path verbatim (no copy of the roll-then-mitigate logic); the `destroy` arm reuses the slice-323 event rather than a parallel kill path. **SRP** the helper does one thing (per-target arm selection + emission); arm *kinds* are a discriminated union so new kinds are localized additions. **Magic numbers** the 100 threshold + 12d12 live in pack content (RAW-cited), not code; the test names `DEATH_SAVE_FAILURES_TO_DIE` and the dice bounds. **at-threading** single `at` passed through every emitted event; the damage arm threads `causedByEventId` to the declared cast. **Mechanical outcomes asserted** CreatureDestroyed vs DamageApplied per arm, post-apply HP (0 + 3 death-save failures on destroy; 150 - rolled on damage), boundary at exactly 100. **Tests** prevent the arm-selection inverting, the destroy arm rolling damage, and non-deterministic replay. No em/en dashes. `tsc --noEmit` clean.
