**Test (slice 425): ground-truth background skill-proficiency conformance**

Fifth 🟡→🟢 ledger upgrade, and a re-verification of the slice-412 fix against the SRD. New [tests/audit/srd-background-skill-conformance.test.ts](../../tests/audit/srd-background-skill-conformance.test.ts) parses each background's granted skills from `character-origins.md` (`**Skill Proficiencies:** Insight and Religion`) and asserts a character of that background is proficient in **exactly** those skills. Built on a Fighter (its own skills are an unresolved pick-N choice) + a Human (no fixed skill grants) with uniform ability modifiers, so the proficiency bonus is the only mover and the proficient set is exactly the background's. Covers the 4 SRD backgrounds in the starter pack (Acolyte insight/religion, Criminal sleight-of-hand/stealth, Sage arcana/history, Soldier athletics/intimidation). A background whose pack skill list drifted from the SRD, or a derivation that dropped background skills (the slice-412 bug), cannot pass.

No engine/content change: the slice-412 fix holds and the pack lists match the SRD; the value is the non-circular verification. Class-choice skills (pick-N) stay 🟡 (no fixed expectation to pin); tool proficiencies stay 🟡. Skips when the SRD clone is absent. Ledger updated: background skill proficiency is now 🟢; scoreboard records five upgraded derivations (421-425), with class-choice skills / passives / speeds / finesse-ranged ability choice / tool prof still 🟡.

**Test (slice 424): ground-truth saving-throw proficiency conformance**

Fourth 🟡→🟢 ledger upgrade. New [tests/audit/srd-saving-throw-conformance.test.ts](../../tests/audit/srd-saving-throw-conformance.test.ts) parses each class's two fixed save proficiencies from its Core Traits table in `classes.md` (`<td>Saving Throw Proficiencies</td><td>Dexterity and Charisma</td>`) and asserts the engine makes a character of that class proficient in **exactly** those two saves. Every ability is given the same modifier, so the proficiency bonus is the only thing that can move a save total — which pins *which* saves the engine treats as proficient against the SRD-named pair. A class wired with the wrong saves (e.g. Fighter as STR+DEX) cannot pass. Covers all 12 classes (verified: Barbarian STR/CON, Bard DEX/CHA, Cleric WIS/CHA, Druid INT/WIS, Fighter STR/CON, Monk STR/DEX, Paladin WIS/CHA, Ranger STR/DEX, Rogue DEX/INT, Sorcerer CON/CHA, Warlock WIS/CHA, Wizard INT/WIS).

Pattern-checked the slice-412 bug class (structured proficiency field not reaching the effect stack): unlike background skills, `computeSavingThrow` reads class save proficiencies through a dedicated `isSaveProficient` helper that consults the structured `class.savingThrowProficiencies` directly, so they were already applied correctly — no bug, clean verification. Effect-granted save proficiency (Slippery Mind etc.) stays 🟡. Skips when the SRD clone is absent. Ledger updated: per-class saving-throw proficiency is now 🟢; scoreboard records the four upgraded derivations (421-424), with skills / passives / speeds / finesse-ranged ability choice still 🟡.

Audit (test slice): no engine/content/public-surface change (no contract-snapshot diff). **Names** `srd-saving-throw-conformance` / `parseClassSaves` / `buildClassCharacter` say what they do. **DRY** one parse of `classes.md` feeds every per-class assertion; `ABILITY_SCORES` drives the per-ability loop. **SRP** the test parses + recomputes + compares; the rule stays in `computeSavingThrow`. **Magic numbers** the save pairs are parsed from the SRD; the uniform score carries its intended mod in a comment. **Mechanical outcomes asserted** all 12 classes parsed with 2 saves each; per class, the SRD pair = mod + PB and the other four = mod. `tsc --noEmit` clean; full suite green (342 files / 2305 passing). No em/en dashes.
