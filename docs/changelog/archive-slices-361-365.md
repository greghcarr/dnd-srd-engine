**Audit: Custom-handlerId backing guard (slice 365)**

New describe block in [tests/audit/pack-integrity.test.ts](../../tests/audit/pack-integrity.test.ts): every pack `Custom { handlerId }` marker must have a backing implementation. A handlerId with no handler is a do-nothing feature. The guard asserts each of the 17 handlerIds is either referenced by name in the engine source or on a documented `BACKED_INDIRECTLY` allowlist (2 entries: `martial-arts`, backed by the attack planner's `martialArtsDie` / `applyMartialArtsDieScaling` which key off the monk class + weapon rather than the id string; and `slow-fall`, backed by `planFalling`'s `useSlowFall` arm). A companion accuracy check fails if an allowlisted handler vanishes from the pack or becomes referenced by name (then it's redundant and should be dropped). Reuses the source-scan pattern already used by the condition-reachability guard; hoisted that describe's `collectTsFiles` helper to module scope so both share it.

This is the last of the silent-failure guards flagged in the slice-363/364 review: a renamed planner that leaves a handlerId marker pointing at nothing now fails CI.

Uncle Bob audit (test slice): **Names** `BACKED_INDIRECTLY` / `referencedInSource` read as what they do. **DRY** `collectTsFiles` hoisted and shared with the condition-reachability guard; handlerIds derived from the pack via the existing `collectRefsByKey` walker, not hardcoded. **SRP** two checks (backing + allowlist accuracy), each one assertion. **Magic numbers** none. **Tests** prevent a do-nothing Custom marker and allowlist rot (a handler that gained a literal reference or left the pack). No em/en dashes. `tsc --noEmit` clean; pack-integrity now 22 checks (was 20).

**Audit: planner-wiring guard (slice 364)**

New [tests/audit/planner-wiring.test.ts](../../tests/audit/planner-wiring.test.ts) closes the one unguarded site in the ~6-site planner wiring. tsc already enforces the `plan/index.ts` export, the `engine/index.ts` import / `Engine.plan` interface method / impl, and apply.ts is exhaustive over the event union; but the `performIntent` dispatch in conveniences.ts is a plain `Record<string, ...>`, so a player-action planner can be wired everywhere else yet silently omitted from dispatch (then `performIntent({ type: 'NewThing' })` throws "Unknown intent type" only when a consumer happens to call it).

The guard uses the allowlist pattern (same shape as pack-integrity's `EFFECT_LESS_OK`): every method on `engine.plan` (99 today) must be either routed by the `performIntent` dispatch (43) or on the documented `EXCLUDED_FROM_DISPATCH` allowlist (56: reactions, per-moment ticks, encounter lifecycle, transformations, sensor/illusion management, item-use, and special-cast planners that don't fit the intent -> events -> commit shape). Adding a planner now forces a conscious choice: dispatch it or allowlist it. Three companion checks keep both sides honest: dispatch targets must be real planners, allowlist entries must be real planners (no rot), and the two sets must not overlap. The engine surface is introspected at runtime (`Object.keys(engine.plan)`) and the dispatch targets parsed from the canonical `engine.plan.X(campaign.state, i)` shape, so the audit tracks the real wiring rather than a hand-maintained list. [CLAUDE.md](CLAUDE.md)'s "Planner shape" section now points at the guard.

Uncle Bob audit (test slice): **Names** `dispatchTargets` / `EXCLUDED_FROM_DISPATCH` / `planners` read as what they hold. **DRY** the planner set is derived from the live engine and the dispatch set from the source, not duplicated; the allowlist is the only hand-maintained list and it is the deliberately-out-of-dispatch set. **SRP** four focused checks (unaccounted, stale dispatch, stale allowlist, overlap), each one assertion. **Magic numbers** none. **Tests** prevent a forgotten `performIntent` dispatch entry (the silent gap), a stale dispatch target, allowlist rot, and a planner being both dispatched and excluded. No em/en dashes. `tsc --noEmit` clean; full suite green.

**Audit: content cross-reference + effect-less-condition guards (slice 363)**

Two new content-integrity guards in [tests/audit/pack-integrity.test.ts](../../tests/audit/pack-integrity.test.ts), each catching a class of silent bug that today only surfaces via a manual sweep:

1. **Content cross-references resolve.** Every `spellId` (GrantSpell / OfferChoice options), `parentClassId` (subclasses), `enchantmentDefinitionId` (magic equipment overlay), and condition-id reference (`conditionId` / `conditionOnFail` / `conditionOnSuccess` / `allyConditionId` / `applyConditionId` / `bearerConditionId`) must resolve to a defined entity in the pack. A renamed or deleted id that leaves a dangling reference (the grant silently never resolves) now fails CI. Greenable today: zero dangling references across all checked key types.

2. **Wired spells don't apply effect-less conditions.** A spell that ships `mechanicalEffects` but applies a condition whose `effects: []` is empty does nothing mechanically on application. Slice 361 swept all such cases by hand; this makes the sweep permanent. Legitimate empty-effect conditions are enumerated in a documented `EFFECT_LESS_OK` allowlist (engine-hardcoded base RAW conditions, engine-read markers `guided` / `mirror-image-active`, the four known-open bugs from slice 361, and the consumer-managed / narrative placeholders). A companion accuracy check fails if an allowlisted condition vanishes or *gains* effects, so when a known-open bug (e.g. `resisted`, `hideous-laughter-active`) is fixed, the audit forces it off the allowlist.

Both extend the existing pack-integrity machinery (a shared `collectRefsByKey` walker; the allowlist-accuracy pattern already used for dead-orphan conditions). This is the "promote a repeatable sweep to a permanent audit" norm again (after gaps-spells-counts and the slice-362 doc-counts audit); the slice-361 starter-pack-gaps note that recommended this guard is updated to mark it shipped.

Uncle Bob audit (test slice): **Names** `collectRefsByKey` / `EFFECT_LESS_OK` / `conditionsAppliedByWiredSpells` read as what they do. **DRY** the recursive ref-walker is factored once and shared by both guards; id sets are derived from the pack, not hardcoded. **SRP** each guard checks one invariant; the cross-ref guard is parameterized by a key→id-set map so a new reference type is a one-line addition. **Magic numbers** none. **Tests** the cross-ref guard prevents dangling spell/class/item/condition ids; the effect-less guard prevents a wired spell applying a do-nothing condition; the accuracy check prevents the allowlist rotting. No em/en dashes. `tsc --noEmit` clean; pack-integrity now 20 checks (was 9).
