**Fix (slice 860): off-hand attack must use a different weapon than the main hand — closes `offhand-not-different-weapon`**
RAW (Light property): "That extra attack must be made with a different Light weapon." `planOffHandAttack` checked the off-hand weapon was Light but never that it differed from the main hand, so a creature could make its off-hand (extra) attack with the very weapon it just struck with. The planner now rejects an off-hand weapon whose **instance** equals `equipped.mainHand` — instance-level, so dual-wielding two of the same TYPE (two Shortswords) stays RAW-legal; only reusing the same weapon in both hands is barred. The `off-hand-attack` bonus-action affordance (`owns: wieldsLightWeapon`, consumer supplies the off-hand `weaponInstanceId`) is by-design a seam with the planner as the gate; the slice-762 affordance test, which exercised a RAW-invalid single-dagger loadout, was corrected to a two-dagger dual-wield. New 2-test slice-860 (off-hand attack with the main-hand instance throws; a different Light instance — incl. a second dagger of the same type — strikes). All existing off-hand tests + the showcase golden stay green. No content/snapshot change. `tsc` clean; `test:fast` (638 files, 4806 passed) + doc audits green.

**Fix (slice 858): auto-crit vs Paralyzed/Unconscious honors within-5-ft (no reach over-grant) — closes `auto-crit-reach-overgrant`**
RAW: "Any attack that hits the creature is a critical hit if the attacker is within 5 feet." Slice 568 used `attackKind === 'melee'` as the within-5 proxy, so a 10-ft reach weapon (glaive/halberd/pike/whip) auto-crit when RAW forbids it. Now within-5 is resolved **precisely from positions** (`chebyshevDistance(attackerPos, targetPos) <= 5`, the same derivation Pack Tactics / ally-adjacent use) when both combatants are positioned in an active encounter — so a reach weapon used adjacent still auto-crits and one at 10 ft does not. **Position-less** falls back to a weapon-reach proxy: a non-reach melee weapon is always within 5 ft, but a reach weapon does NOT auto-crit without positions. New 2-test slice-858 (position-less: a longsword hit auto-crits a paralyzed target, a glaive hit does not — same seed/d20, isolating the auto-crit; positioned: a glaive auto-crits at 5 ft but not at 10 ft, via seed-iteration to a non-natural-crit hit). The slice-568/805/611/575 auto-crit tests stay green (their weapons are non-reach). No content/snapshot change. `tsc` clean; `test:fast` (637 files, 4804 passed) + doc audits green.

**Fix (slice 857): Graze (and the weapon-mastery save DC) read effective STR, not base — closes `graze-hardcodes-str`**
RAW Graze deals damage equal to "the ability modifier you used"; the engine computed it from the raw snapshot STR (`abilityModifier(attacker.abilityScores.STR)`), so a Greatsword wielder with Gauntlets of Ogre Power (STR set to 19) dealt Graze from their unmodified score, ignoring the item. A shared `effectiveStrMod` helper now reads the **effective** STR modifier (`effectiveAbilityScore` over the effect stack's ability-score floor / increase — the same derivation the attack planner uses). **Pattern-check:** `masterySaveDC` (the weapon-mastery save DC, used by Topple) had the identical base-STR bug — fixed in the same slice (it now takes attacker + state + content and uses `effectiveStrMod`). New 3-test slice-857 (a STR-8 Greatsword wielder with Gauntlets deals 4 Graze, not 0; without Gauntlets deals none; Topple DC reads effective STR, Gauntlets raise it 10 → 15). The s23-weapon-mastery golden + slice-380/502/624/626/853 mastery tests stay green (their attackers have base STR = effective STR). No content/snapshot change. `tsc` clean; `test:fast` + doc audits green.
Detail: [slice-857.md](slice-857.md).

**Docs (slice 856): `half-caster-l1-slot` is NOT A BUG — stale 2014 finding**
The audit row read "a single-class L1 Paladin/Ranger shows a 1st-level slot (`ceil(1/2)=1`); RAW spellcasting starts at L2" — but "starts at L2" is the **2014** rule. SRD 5.2.1 (2024) `classes.md` lists "**Level 1: Spellcasting**" for the Paladin (and Ranger), and the Paladin Features table grants **2 first-level slots at Level 1**. So a single-class L1 Paladin/Ranger *should* have 2 first-level slots — `ceil(1/2)=1 → row 1 = [2]` is correct, deliberately implemented in slices 564/574. The third-caster `level < 3` guard is right (EK/AT genuinely gain Spellcasting at L3 in 2024); the half-caster has no such guard because there's nothing to guard — adding one would be 2014 edition drift. The row is struck (NOT A BUG) + a bullet added to "Confirmed correct / by-design"; a `spell-slots.ts` comment records why there's no half-caster L1 guard; new 3-test slice-856 pins it. The `level < 2 → 0` "fix" was tried and **reverted** — it broke 8 existing tests that correctly assert L1 = 2 slots. Same misread-the-edition pattern as slices 841/842. Doc + test + comment only; no behavior change. `tsc` clean; `test:fast` + doc audits green.

**Fix (slice 855): Grapple / Shove saves go through the full derivation — closes `hand-rolled-saves-bypass-stack`**
The third and last arm of the raw-mod-save-bypass pattern (after 853 Topple / 854 Open Hand). The 2024 Grapple and Shove (Unarmed Strike options) resolve on a target STR-or-DEX save vs the attacker's unarmed DC; `planGrapple` / `planShove` in `contested.ts` hand-rolled both as `abilityModifier(target.abilityScores[...])`, bypassing `computeSavingThrow` — skipping save **proficiency**, Bless/Bane bonus dice, advantage/disadvantage, Magic Resistance, and the auto-fail. Both now route through the shared `rollSaveAgainstDC` (`sourceIsMagical: false` — an Unarmed Strike is nonmagical). Import cleanup was careful: `contested.ts` has a third roll (`planHide`'s Stealth ability check, already derived) sharing `rollDie`/`D20_SIDES`/`applyHalflingLuckFromFlag`, so only `applyHalflingLuckForCharacter` + the `SaveRolledEvent` type were removed. The `s21-contested` golden was regenerated: its two Fighter-built grapple/shove victims now correctly add their +2 STR-save proficiency (Goblin Boss +1→+3, Cutter −1→+1) — both still fail DC 15, so outcomes are unchanged. New 3-test slice-855 (Grapple save carries a breakdown; a STR-save-proficient Fighter target adds proficiency to both Grapple and Shove, +4 vs a non-proficient Wizard +2). slice-803 + s15/showcase goldens unchanged; no content/snapshot change. `tsc` clean; `test:fast` + doc audits green.
