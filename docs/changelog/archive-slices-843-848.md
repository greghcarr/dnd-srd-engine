**Docs (slice 848): `heroism-no-recurring-temp-hp` is NOT A BUG — stale L7 finding**
The audit row ("`heroic-active` grants only Frightened immunity; RAW also grants temp HP = spell mod each turn") looked only at the **condition**. The temp HP **is** fully modeled — by design not on the condition but on the spell's **`recurring` SpellMechanic** (`{ effect: 'temp-hp', addCasterAbilityMod: 'CHA' }`), driven by `planTickRecurring` / `engine.plan.tickRecurring` (the slice-79 primitive): each target turn-start grants the caster's CHA modifier (RAW "your spellcasting ability modifier", CHA for Bard/Paladin) as temp HP with RAW **max-not-stack** semantics (`applyTempHPGranted` keeps the higher). `heroic-active`'s own description already says the grant "fires via engine.plan.tickRecurring … (not stored on this condition)." Same misread-the-surface pattern as slices 841/842. The row is struck through (NOT A BUG) and moved to "Confirmed correct / by-design"; new 3-test `slice-848` guard pins the recurring temp-HP mechanic shape + the per-tick CHA-mod grant that refreshes rather than stacks (the functional grant has been covered since slice 79 by `recurring-tick.test.ts`). Doc + test only; no source change. `tsc` clean; `test:fast` + doc audits green.

**Feat (slice 846): Heat Metal damage ignores the save — closes `heat-metal-save-on-wrong-arm`**
RAW 2024 Heat Metal deals 2d8 fire automatically; the CON save only decides drop-object / Disadvantage. The pack wired it as a `save` with `halfOnSuccess: false`, so a successful save **negated the damage entirely** (backwards). New opt-in **`SpellSaveMechanicSchema.damageIgnoresSave`** flag: the single `outcomeAmount` chokepoint in `cast-spell.ts` returns the raw damage regardless of the save when set, and the save governs only `conditionOnFail` — composing with `extraDicePerSlotLevel` (full upcast) and `additionalDamage`. Unset → historical behavior, so every other save spell is byte-unchanged. Heat Metal rewired to `{ save CON, 2d8 fire, damageIgnoresSave, conditionOnFail: heat-metal-gripped }`; new **`heat-metal-gripped`** condition applies Disadvantage on attack rolls + ability checks (Frightened's shape minus the LoS gate) with `autoExpiry { 1 round, turnStart }` (= "until the start of your next turn"). The "drop the object" branch stays consumer/DM-narrative (held-item state unmodeled). +1 condition (168 → 169; rider 153 → 154); citations bumped. New 4-test slice-846 (full 2d8 on a SUCCESSFUL save with no grip; full 2d8 + grip on a failure; slot-3 upcast rolls above the 2d8 ceiling). `tsc` clean; `test:fast` + doc audits green.

The consumer ticks `tickRecurringDamage` + `tickRecurringSave` at the target's turn-start. Upcast (+1d6/slot) deferred (static condition dice, as with every smite). +1 condition (167 → 168; rider 152 → 153) — bumped the getting-started/status/starter-pack-gaps citations; coverage snapshot unaffected.
