**Test (slice 421): ground-truth AC conformance — first 🟡→🟢 coverage-ledger upgrade**

Starts converting the character-sheet derivations from 🟡 probe-tested (author-asserted) to 🟢 ground-truth (verified against the SRD text), per the [coverage ledger](../srd-coverage-ledger.md). New [tests/audit/srd-ac-conformance.test.ts](../../tests/audit/srd-ac-conformance.test.ts) parses the **Armor table out of `references/srd-markdown/equipment.md`** and recomputes each armor's AC straight from the table cell — base AC and the Dex-cap semantics both come from the cell text (`"11 + Dex modifier"` → full Dex; `"14 + Dex modifier (max 2)"` → cap 2; flat `"16"` → no Dex; `"+2"` → shield) — then asserts `computeAC` agrees across all 12 SRD armors × a Dex range spanning negative / zero / capped / high modifiers, plus the shield over unarmored AC. Because the expected values are parsed from the book, a misread base or Dex cap in the engine cannot pass: this is the model the ledger's other 🟡 derivation rows (saves, skills, spell DC, speeds) should follow.

No engine change: `computeAC` was already SRD-correct; the value is the **non-circular verification**, not a fix. Skips (does not fail) when the SRD clone is absent, mirroring srd-drift. Ledger updated: worn-armor + shield AC is now 🟢 (natural/statblock armor stays 🟡); scoreboard notes AC as the first upgraded derivation.

Audit (test slice): no engine/content code change, no public-surface change (no contract-snapshot diff). **Names** `srd-ac-conformance` / `parseArmorTable` / `dexContribution` say what they do. **DRY** parses the SRD cell once into a per-row `dexContribution`; the assertion loop reuses it across the Dex range. **SRP** the test only parses + recomputes + compares; the AC rule stays in `computeAC`. **Magic numbers** none transcribed — base + cap are parsed from the SRD; the one transcribed constant (unarmored base 10) carries its SRD quote. **Mechanical outcomes asserted** every SRD armor's AC = parsed-base + parsed-Dex-rule at five Dex scores; shield = +2; a parse-sanity floor (≥12 armors, shield = +2) keeps it non-vacuous. `tsc --noEmit` clean; full suite green (339 files / 2244 passing). No em/en dashes.

**Docs/infra (slice 420): SRD rule-coverage ledger + trustworthiness-roadmap recalibration**

Answers "how do I know the engine actually enforces the SRD, vs just agreeing with the author who wrote both the code and its tests?" New [docs/srd-coverage-ledger.md](../srd-coverage-ledger.md): a living, per-rule inventory tagging each SRD mechanic 🟢 ground-truth (expected value derived from the SRD text, non-circular: srd-drift / boundary tables / transcribed examples), 🟡 probe-tested (author-asserted; catches regressions, not original misreadings), or 🔴 unverified. It names the circularity trap explicitly (a green suite proves consistency-with-the-author's-reading, not SRD-correctness), seeds the ledger from the rules that have evidence today (core-math tables, content-data fidelity, sheet derivations, the 48 RAW-compliance probes, conditions, combat math, spellcasting, rest, progression), and is honest that the unlisted rules are themselves the biggest blind spot.

[docs/trustworthiness-roadmap.md](../trustworthiness-roadmap.md) recalibrated from slice ~196 to 419: new "How we verify (and the circularity trap)" section; current-state bullets updated (srd-drift now covers class progression tables, the read-layer view models are flagged as the black-box surface for ground-truth upgrades); Tier 4 marked substantially-achieved-in-place (the starter pack is SRD-only since slices 400-403); two stale "still open" Tier 3 items struck through (Fighting Style track complete; trigger-applied-condition auto-expiry shipped).

New CI guard [tests/audit/coverage-ledger.test.ts](../../tests/audit/coverage-ledger.test.ts) pins the ledger's machine-derivable anchor counts (48 RAW-compliance probes, 7 boundary table groups) to the live suite so the ledger can't overstate coverage as the suite changes. Both new docs registered in the doc-size audit's fixed-file list.

Surfaced + fixed an off-by-one while building the guard: `grep -c 'it('` counts an `it()` mention in a comment, so the true probe count is 48 (not 49); the guard now matches line-start `it(` and the count is corrected across the ledger, roadmap, and status.md (a fitting mini-instance of the very circularity the ledger is about — a count derived from the same flawed source it was meant to verify).

Audit (docs/infra slice): no engine/content code change, no public-surface change (so no contract-snapshot diff). Names: ledger / roadmap / guard are intention-revealing. The guard verifies only machine-derivable anchors, not the human-maintained G/P/U judgments. `tsc --noEmit` clean; full suite green (338 files / 2230 passing). No em/en dashes.
